# Authentication & RBAC Model

Straw uses a token-based authentication model to identify clients, operators, and workers. Authenticated clients are authorized using Role-Based Access Control (RBAC).

---

## Authenticating API Requests

API calls to Straw's Control plane must include a Bearer token in the `Authorization` HTTP header:

```http
Authorization: Bearer sk_example_...
```

To prevent token enumeration attacks:
- API key verification uses a constant-time comparison helper.
- Any auth check failure returns a generic `401 Unauthorized` status with the code `auth_failure`. It does not expose whether the key was invalid, revoked, or non-existent.
- Tenant-scoped keys linked to a suspended, deleted, or missing tenant return `401 Unauthorized` with the code `tenant_not_found`.

---

## API Key Scope Types

Every API key generated by Straw has a distinct Scope Type that determines its security isolation boundary:

1. **Platform Scope (`platform`)**:
   - Intended for platform operations and cross-tenant systems.
   - Do not belong to any tenant (`tenant_id` is null).
   - Only support the `system_admin` role.
   - **Important**: Platform-scoped keys can never execute egress requests (`POST /api/v1/requests`).
2. **Tenant Scope (`tenant`)**:
   - Configured for a single specific tenant ID.
   - All actions and resources mutated by the key are forced to that tenant's boundary.
   - Support `tenant_admin`, `operator`, `viewer`, and `requester` roles.

## API Key Secret Generation & Hashing

When creating API keys:
1. The client receives a generated raw secret string.
2. Straw computes a SHA-256 hash of the token combined with a system-configured pepper (`STRAW_API_KEY_PEPPER`).
3. Only the hash and a short visible prefix are stored in the database.
4. If a token is compromised, a tenant administrator can immediately call the corresponding `/revoke` endpoint.
