Task number 15 is retired: the old task 15 file was renumbered to 25 so the board stays in dependency order.

Tasks 27-34 were added by the 2026-07-04 planning-vs-implementation review: tasks 01-26 satisfy their own
acceptance criteria, but several `docs/planning` P0 items (admin request cancel, Control `/metrics`, the remaining
tenant/executor-pool/`changes` config endpoints, request-outcome telemetry) were unbuilt and unowned. Each new task
is a vertical slice grounded in a named planning section.

Tasks 39-41 were added by the 2026-07-05 live end-to-end verification, which ran the full compose stack and drove a
real REST -> NATS -> egress -> upstream request (fixing the ClickHouse timestamp-format insert failure, the missing
egress pool declaration, and the missing tenant first-key bootstrap in the same session). The three new tasks own
the gaps that verification exposed but did not fix: the Postgres test harness truncating live databases (and leaking
fixtures into them), egress exiting fatally when Control is unreachable at registration, and per-phase request
timings recording `egress_ms = 0` on successful ~200ms dispatches. None of the three depend on each other or on
anything beyond the completed 01-38 base.

Tasks 35-38 were added by the 2026-07-04 follow-up review of that batch: registration replay protection plus a
persistent worker identity key (without which the `docs/planning/27` signing control cannot pass in a live stack —
see `deploy/docker/README.md`), the canonical `/api/v1/config` base path for the bare-path config routes, structured
JSON logging per `docs/planning/23`, and egress `/healthz`/`/readyz`. The `log_events` ingestion deferral is owned by
`docs/tasks/p1/20-log-events-ingestion.md`.

### Dependencies among tasks 27-38

No hard logical dependencies exist between these tasks: every one's Prerequisites are satisfied entirely by the
completed 01-26 base, so no new task blocks another. The High-to-Low severity order is therefore a valid execution
order, not a required one — any order works. The only couplings are shared files (a merge concern, not a logical
dependency):

| Shared file | Tasks that modify it |
|-------------|----------------------|
| `cmd/control/main.go` (route/startup wiring) | 27, 28, 29, 30, 31, 32, 35, 36, 37 |
| `cmd/egress/main.go` | 35, 37, 38 |
| `internal/control/dispatcher.go` | 27, 28, 32 |
| `internal/control/admin_handlers.go` | 29, 30 |
| `internal/control/config_admin_handlers.go` | 30, 31 |
| `internal/control/request_metadata.go` | 28, 32 |
| `internal/config/config.go` | 35, 38 |

Work these serially, or expect a rebase if they are branched in parallel. Tasks 33 and 34 touch no shared files and
can run at any time. Two soft orderings: land 36 before 29/30/31 (they register new routes only under the canonical
base path 36 establishes), and note that 38's `/readyz` only turns green in compose once 35 makes live registration
succeed (the endpoint itself is testable without it).

Tasks marked done before the audit are done for their (narrow) library scope only. The audit corrections in
`docs/agents/handoffs/05-*.md`, `docs/agents/handoffs/11-*.md`, and task 03's unchecked wiring step record
where the original claims overstated integration.

## Rules

- Start from `AGENTS.md`.
- Read the task file before editing.
- Do not skip prerequisites.
- Run `make check` before handoff.
- Use `docs/agents/templates/handoff.md` for handoff.
- Follow the Completion Audit in `.llm-docs/skills/straw-task-runner/SKILL.md`: a wiring step is only done when
  the built binary constructs the real component, and every deferral must name the owning task file.
